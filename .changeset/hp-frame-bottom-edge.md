血條判讀改成先找外框再讀框內。之前是從血色往左右爬，已損失區一變白或變成別的顏色就停在半路，19.8% 的血會讀成 48%。

外框的下邊是固定三層結構：白線、上一列中灰內襯、再上一列暗色。只驗「白」會把場景裡的白色物件也收進來（實測讓下邊線多長 80px），加驗「白線正上方一定比它暗」之後就分得開了——真下邊線的亮度落差最低 11.1，純白場景是 0.0。下邊線被 UI 蓋掉一半時（只剩 47% 是白）靠「缺口上方是不是還是血條」把斷開的白段接回同一條線。

框內讀哪幾列，用「血條的一列只有兩種顏色」來挑：蓋在血條上的面板會多出好幾群顏色，兩色比掉到 50~71%，乾淨的血條列是 88~100%。剩餘時間面板蓋住血條下半部時，原本會把面板左緣當成血量分界，讀成 16% 而不是 29%。

分界點改成找最佳分割點（左邊盡量是剩餘色、右邊盡量是已損失色），不再數「第一群顏色連續到哪」——一個壓縮雜訊像素就會把 run 切斷，真分界在 x432 卻讀到 x394。

八張實戰截圖的誤差全在 ±0.3% 內（原本系統性低估 1.2%），2K 完全準確。順帶修掉兩件事：血量低於 1.2% 時會讀成 0%，以及整條同色時分不出滿血與空血（王被打死那一刻會讀成 100%）。
